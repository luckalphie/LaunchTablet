# 给 Java 开发者的代码导读

这个项目运行在 macOS 桌面进程中。可以先理解为：一个主线程持续接收系统事件，后台任务读取应用目录，界面根据页面状态自动更新。

## 建议阅读顺序

1. `LaunchTabletApp.swift`：main 入口、程序启动、窗口显示/隐藏、键盘与滚轮事件。先理解窗口为什么覆盖整个屏幕，以及 Esc 从哪里进入。
2. `LauncherModel.swift`：页面状态和交互动作。作用类似 Service + ViewModel，串起搜索、分页、启动应用、文件夹和保存布局。
3. `LauncherView.swift`：界面布局。`body` 根据 Model 状态描述搜索框、当前页、文件夹和设置弹层。
4. `LauncherLayout.swift`：可序列化的数据结构、排序/分组规则以及 JSON 文件的读写。纯布局规则不调用 AppKit。
5. `ApplicationCatalog.swift`：读取应用 bundle、生成搜索索引、缓存图标、监听安装目录。
6. `LauncherDragSource.swift`：通过 `NSViewRepresentable` 接入原生拖拽源与投放目标。
7. `GlobalShortcut.swift` 和 `LauncherIcon.swift`：系统快捷键注册与原生图标绘制。

所有文件属于 `LaunchTablet` 模块，目录层级不等同于 Java 的 package 命名空间。默认的 `internal` 可见性覆盖当前模块，`private` 用于限制实现细节。

## 常见语法与概念

| Swift 写法 | 在本项目中的含义 |
| --- | --- |
| `let` / `var` | 不可重新赋值的绑定 / 可重新赋值的变量。`let` 引用一个 class 时，其对象内部仍可能可变 |
| `struct` | 值类型。布局、应用元数据采用值语义；数组、字典会按需复制，避免共享集合被随手修改 |
| `class` / `final class` | 引用类型。Model 需要被 View 和窗口协调器共享；`final` 表示不可继承 |
| `String?` / `if let` / `guard let` | 显式可空类型以及解包。`guard` 的失败分支通常提前 return，后续代码使用非空值 |
| `Codable` | 编译器可为结构体生成 JSON 编解码实现，类似常规 DTO 配合 Jackson 的用途 |
| `ObservableObject` + `@Published` | Model 发布属性变化，订阅它的 SwiftUI View 自动更新 |
| `@ObservedObject` | View 观察外部传入的 Model，其生命周期由上层持有者管理 |
| `@State` | View 自己的局部状态，例如图标是否悬停、文件夹标题草稿 |
| `$model.query` | 可读写绑定，文本框输入会回写 Model 中的 query |
| `@FocusState` | 声明式管理输入焦点，控制搜索框/文件夹名称是否接收键盘输入 |
| 闭包 `{ ... }` | 类似 Java lambda，可作为事件回调或后台任务传递 |
| `[weak self]` | 回调不强引用所属对象，避免 ARC 引用计数下的循环引用；对象已释放时 self 为 nil |

SwiftUI 的 `body` 会被多次重新求值，因此目录扫描、文件写入、应用启动都放在 Model 的动作中。View 只组织控件和绑定事件。

## 主线程与后台任务

`NSApplication.run()` 在主线程运行事件循环，AppKit 控件和窗口也由主线程操作。

Model 上的 `@MainActor` 让可见状态在主线程串行更新。可以将它理解为把 UI 状态操作提交到指定执行器。它约束调用位置，不负责把阻塞工作自动移动到后台。

应用扫描使用 `Task.detached` 执行文件遍历、Bundle 信息读取和拼音转换。`await` 等待结果期间不会阻塞 UI；拿到结果后回到 MainActor，再更新 `@Published` 属性。传递的数据只有 URL 和字符串，图标等 AppKit 对象留在主线程。

文件夹排序操作修改 `LauncherLayout` 值；磁盘扫描和异步回调更新页面状态时，也统一回到 Model。这样界面不会同时从多个线程修改同一份数组。

## 两套 UI 框架怎么配合

AppKit 提供 `NSApplication`、`NSWindow`、`NSWorkspace` 等系统接口。SwiftUI 用 `View` 描述窗口内部的布局；`NSHostingView` 把 SwiftUI 界面嵌入 AppKit 窗口。

本项目自行管理无边框 `NSWindow`，将其尺寸设成当前屏幕的 `frame`，从而覆盖当前桌面。内容网格再限制到中央区域。这里没有调用进入原生全屏 Space 的 API，因此呼出和收起不需要桌面切换动画。

屏幕尺寸使用逻辑点。Retina 屏幕一个逻辑点可能对应多个物理像素，布局无需手动乘二。最大内容尺寸及行列数集中在 `GridMetrics`。

## 键盘和横向分页

窗口协调器使用本进程的本地事件监视器，先于搜索框检查 Esc。处理完成后返回 nil 消费事件；未处理则把原事件交还系统。

Esc 的顺序为：错误提示 → 设置/帮助 → 文件夹 → 搜索词 → 收起窗口。原生右键菜单正在跟踪时，事件留给菜单；文件夹名称编辑、设置控件内的方向键也不交给网格。

触控板的滚动包含手势阶段与惯性阶段。累计横向位移到阈值后翻一页，并锁住该轮手势；忽略后续惯性，下一轮手势再解除。普通鼠标的离散滚轮事件没有相同的手势语义，所以单独做节流。

页码从 0 开始；页面圆点展示时加 1。网格是按固定容量切片，最后一页保留空槽位置，因此少量应用不会突然居中或拉大间距。

## 应用 bundle、启动和持久化

macOS 的 `.app` 是包含可执行文件、资源和 `Info.plist` 的目录。`Bundle` 读取它的名称、标识与后台属性；`NSWorkspace` 读取图标并按系统方式启动应用。

布局只记录 bundle ID、文件夹名称和顺序，不存图标或完整路径。图标由 `NSCache` 按需缓存；壁纸先在后台缩略到较低分辨率，再用于模糊背景，控制大屏内存开销。

`LayoutRepository` 通过 JSON 原子写入保存到 Application Support。扫描缺失和合法卸载分开处理：一次读取失败不能导致已有排列被当成“应用全部卸载”清掉。文件无法解析时也不覆盖原文件。

## 日常开发

- 源码运行：`sh scripts/run.sh`。已运行安装版时先退出它，避免两个启动器同时注册快捷键。
- 构建 `.app`：`sh scripts/build-app.sh`。脚本编译 Release、生成图标、写入 Info.plist 并做本地签名。
- 运行检查：`sh scripts/test.sh`。使用 Swift 6 自带的 Testing；Command Line Tools 需要配套 SDK 与宏插件，本机验证通过的组合见 README。
- 导出文档预览：`sh scripts/export-preview.sh`。离屏绘制真实 View，数据和布局全部使用临时示例，不读取用户应用列表或壁纸，不显示窗口。
- 修改中央内容区尺寸：查看 `GridDisplayMode.swift` 中的 `GridDisplayMode` 和 `GridMetrics`。预设上限、缩小条件、图标尺寸放在一起。
- 修改 Esc/方向键规则：查看 `handleEscape`、`handleKey`，同时补相应 Model 检查。
- 修改文件夹/排列规则：先查看 `LauncherLayout`；跨页、焦点和窗口行为在 Model/窗口协调器中处理。

脚本统一通过 `swift-env.sh` 使用 `xcrun` 解析当前 Swift 和 SDK，尊重调用方的 `DEVELOPER_DIR`、`SDKROOT`，不绑定开发机器的 SDK 版本。Swift Testing 的宏插件也从同一个 Swift 工具链中查找，避免 Xcode 与 CLT 混用。

打包时先生成图标，再移除可执行文件中的调试符号，最后做本地临时签名；这样分发包不会携带 Xcode 调试符号记录的本机源码路径。正式分发需要开发者签名与公证。`dist/`、`.build/`、`.swiftpm/` 和本机 Xcode 状态文件不进入 Git。自有代码采用 MIT 许可，应用包和 DMG 内均附带 LICENSE。

## 分类与默认排序的补充说明

`InstalledApplication` 的 `category` 类似 Java 的可空枚举，`nil` 表示应用直接显示在主网格。`ApplicationCategory.from` 只根据标准类别和目录判断，不把未声明类别的普通应用都归入文件夹。Apple 常用应用仍在主网格，系统 Utilities 目录放入“其它”。系统目录以外的 Apple 软件会校验签名。

`LauncherLayout.reconcileApplications` 是布局聚合更新入口：记录首次观测到的安装日期，判断旧 JSON 是否需要迁移，再按自动或手动模式更新。`installationDates` 类似 `Map<String, Date>`，键是 bundle ID；安装日期只在首次发现时采集，避免更新替换 .app 后重排。它是对安装时间的估计，优先取加入目录时间，缺失时使用创建时间。

Swift 的 `Codable` 类似 Java JSON 序列化协议。布局新增字段使用显式 `decodeIfPresent` 兼容旧文件，旧版原有必填字段仍用 `decode`，因此损坏的空 JSON 不会被当成合法空布局覆盖。`LauncherItem` 的可空分类字段由编译器自动兼容缺失字段。

默认模式按 Apple 应用、第三方安装日期、名称和 ID 排序，并生成固定 ID 的分类文件夹；一旦用户拖动或修改布局，Model 保存时标记 `isManuallyArranged`，后续扫描就保留排列。设置中的恢复操作会重建默认布局，但保留隐藏状态。

浏览器网页应用按来源目录识别：`Edge Apps.localized`、`Chrome Apps.localized` 优先归入各自文件夹。扫描时先检查符号链接解析前的目录，避免丢失来源信息；浏览器本体不受此规则影响。`browserGroupingVersion` 用于对旧手动布局进行一次迁移，只收拢主网格和系统分类中的网页应用，保留自建文件夹及隐藏状态。之后新网页应用自动加入对应浏览器文件夹，用户仍可自行调整已有排列。


## 拖拽和动画

`LauncherDragSource` 把透明的 AppKit View 嵌入 SwiftUI 图标。按下后移动超过 6 逻辑点才启动系统拖拽，普通点击仍然打开应用；右键交还 SwiftUI 菜单。私有 UTI 类似一份局部消息类型，投放时同时核对内部拖拽状态和剪贴板 ID，外部文本不能触发布局更新。

`NSDraggingSource` 的 session 结束回调统一清理状态，包括 Esc 取消、无效投放和成功投放。不能依赖原窗口的 mouseUp，因为系统拖拽循环可能消费它。图标投放命中也使用 AppKit，避免透明 NSView 遮住 SwiftUI DropDelegate；空槽、翻页边缘、文件夹外围仍由各自 DropDelegate 处理。

Model 保留 `dragSourceFolderID`，目标容器取当前 `openFolderID`；悬停展开或关闭文件夹只切换展示，不立刻移动数据。真正松手时，Layout 在值类型副本上执行跨容器移动，验证目标后才替换布局。取消或无变化时不写文件，也不把默认排列切成手动模式。

SwiftUI 的 `ForEach` 使用应用/文件夹业务 ID 而非槽位编号，才能识别同一图标从旧位置到新位置，或者从界面移除。`.animation(value:)` 对指定状态变化插值；`.transition` 控制新增/移除。呼出时缩放从 1.12 插值到 1，形成由大变小的落定感；收起时反向播放。内容动画为 0.32 秒，窗口协调器等待 0.34 秒后再 `orderOut`，序号校验避免旧退出回调误关刚重新打开的窗口。系统减少动态效果时禁用缩放、位移与模糊变化，保留短暂淡入淡出。

副屏测试包在 `.build/ui-testing/layout.json` 保存独立布局，不注册全局快捷键。副屏断开时不显示窗口；不会回退到正在使用的主屏。

## 改名与中英双语

`AppIdentity` 集中保存新旧应用标识。Swift 模块、应用包、图标、DMG、用户可见菜单统一为 LaunchTablet；旧 Launchpad 标识仅用于排除自身与数据迁移。新版布局在 Application Support 的 LaunchTablet 目录中，不存在时读取旧目录；下一次保存写新版，旧文件保留。新版损坏不静默回退旧数据。

`Localization.swift` 类似 Java 的 `ResourceBundle` 封装：`TextKey` 约束键名，两份 `Resources/*.lproj/Localizable.strings` 提供文案。`Localizer` 解析“跟随系统/中文/英文”，按当前语言定位资源并格式化参数。运行时从随包资源加载，不依赖开发机器的绝对路径。`swift test` 的宿主不一定是应用：SwiftPM 调试构建使用生成的 `Bundle.module` 访问器；Release 从可执行文件附近找资源，不引用可能包含本机路径的调试访问器。旧 SwiftPM 会将 `zh-Hans.lproj` 输出为小写，资源查询同时兼容两种拼写。

`LauncherModel.language` 是发布属性，变化后 SwiftUI 重新求值；`languageChanged` 同步重建 AppKit 菜单。错误状态保存类型和原始参数，在展示时生成文案，避免切换语言后错误提示仍停留在旧语言。快捷键与语言偏好使用注入的 `UserDefaults`，测试、预览使用独立 suite，不修改日常偏好。

分类枚举的中文 rawValue 已属于旧 JSON 协议，保留不改，只在 `title(for:)` 翻译默认分类。用户自定义名称不翻译。文件夹编辑器记录初始展示名，只有实际修改才保存，避免英文的 Utilities 在打开/关闭文件夹时被当作用户重命名写回布局。

`sh scripts/export-preview.sh` 离屏生成中英文主界面、设置和文件夹预览，均使用隔离示例数据，不打开桌面窗口。打包后可用应用内可执行文件的 `--check-localizations` 参数无窗口核对两份语言资源是否齐备。


## 网格显示范围

`GridDisplayMode` 类似 Java 的配置枚举，提供 `fullScreen`、`macBook14`、`macBook16`、`display24`、`display27` 五种稳定配置值。14 英寸默认上限为 1120 × 790 逻辑点，16 英寸为 1280 × 900，24 英寸为 1920 × 1080，27 英寸为 2160 × 1215，全屏不设笔记本区域上限；所有模式先扣除屏幕边缘留白，再取实际可用尺寸，保持小屏适配。14/16 英寸沿用原有图标大小。全屏左右各留 10%、上下各留 5%，至少分别保留 44/36 逻辑点；超宽屏网格宽高比最多 1.9，其余空间留在两侧。高竖屏使用 5 列 7 行，普通横屏为 7 列 5 行，单页容量同为 35。

`LauncherModel.gridDisplayMode` 通过 `@Published` 驱动 View 重新计算 `GridMetrics`，并将选择写入注入的 `UserDefaults`。缺失或无法识别的值按 14 英寸处理。这个设置只影响显示区域，不写入布局 JSON，也不重排图标或关闭已打开的文件夹。设置选项同步使用中英文资源；离屏预览覆盖五种范围。


全屏和 24/27 英寸预设的图标按真实单元格大小计算，上限分别为 160/112/128 逻辑点，最小为 42 点。计算先扣除搜索栏、分页和单元格间距，再预留随字号变化的名称与内边距，避免最后一行裁切。`captionFontSize` 和 `captionSpacing` 同时供尺寸计算和 View 使用；名称最大为 18 点，图文间距最大为 16 点。文件夹封面的缩略图与原生拖拽预览也沿用当前图标尺寸。


## 翻页动画范围

`GridMetrics.pageViewportWidth` 只控制主网格翻页的绘制边界：全屏取屏幕宽度，其它预设在静止网格左右各增加一个列节距（列宽 + 列间距），最终受屏幕宽度约束。网格本身的尺寸与居中位置独立计算，不为外扩动画缩小原网格。

`PageViewportMetrics` 类似 Java 的纯布局计算对象，将网格宽度、动画视口宽度、页面步长和页内留白分开。每页以外扩后的视口宽度排列，网格居中放在页内；先平移整条页面轨道并按宽视口裁切，再居中回原布局宽度。这样可以看到图标滑出原网格，又不会在静止时露出相邻页面。点击范围和非当前页的辅助功能/点击屏蔽仍按原网格处理。文件夹内分页继续在面板内部裁切。

`PagedApplicationGrid.scrollOffset` 接收已有手势位移；正常界面由 Model 提供，离屏验收可传入固定的 30% 页宽位移，绘制真实网格的翻页中间帧。预览里的细框只标示原网格边界，不进入正常应用界面。
